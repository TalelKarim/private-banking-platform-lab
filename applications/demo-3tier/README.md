# demo-3tier

First real workload consuming the reusable Jenkins -> OpenShift platform foundation.

## Application architecture

```text
Authorised browser / cloud-browser
        |
        | HTTPS
        v
Route53 wildcard -> AWS public ALB (ACM TLS)
        -> edge-gateway Nginx
        -> okd-lb / HAProxy
        -> OpenShift ingress router
        -> Route demo-3tier
        -> Service demo-frontend
        -> 2 x frontend Nginx Pods
             |
             | /api/* using Kubernetes DNS
             v
           Service demo-backend
             -> 2 x Python backend Pods
                    |
                    | PostgreSQL protocol :5432
                    v
                  Service demo-postgres
                    -> StatefulSet demo-postgres-0
                         -> PVC postgres-data-demo-postgres-0
                         -> StorageClass cinder-standard
                         -> Cinder CSI
                         -> OpenStack Cinder volume
```

The AWS ALB is Internet-facing, but the existing lab Security Group intentionally restricts HTTP/HTTPS to the configured lab client CIDR and optional cloud-browser EIP. Phase 3 reuses the existing `*.apps.okd.lab.talelkarimchebbi.com` Route53/ACM/ALB/Nginx path; it does not open the application to every Internet source.

## Components

- `frontend/`: OpenShift-compatible Nginx image, static UI and `/api/` reverse proxy.
- `backend/`: tiny Python HTTP API using PostgreSQL through `psycopg`.
- `openshift/configmap.yaml`: non-secret backend connection settings.
- runtime Secret `demo/demo-postgres-credentials`: generated by platform automation, never committed.
- `openshift/postgres.yaml`: headless Service + single-replica StatefulSet + 5 GiB Cinder PVC.
- `openshift/backend.yaml`: Service + two-replica Deployment.
- `openshift/frontend.yaml`: Service + two-replica Deployment.
- `openshift/route.yaml`: public OpenShift Route under the existing apps wildcard.
- `openshift/imagestreams.yaml`: ImageStreams receiving Jenkins-built images.
- `Jenkinsfile`: checkout -> authenticate -> build -> push -> deploy -> E2E test.

## Commands

From `ops-runner` after Phase 2 is healthy:

```bash
make configure-demo-3tier
make deploy-demo-3tier
make test-demo-3tier
```

`make configure-lab` also converges and validates Phase 3 automatically.

The normal browser URL is:

```text
https://demo.apps.okd.lab.talelkarimchebbi.com
```
